# Follow-up permutation-scratch liveness proof — not implemented

Read-only audit at within merge69110db and registry approx-chol0.5.0 (crate VCS36f07b1dfc6300deb790a29053a56d8718dede54, path crates/approx-chol). Current BlockElimSolver uses two equal buffers of S=N+R+H entries, where N=L+K is local dimension, L is eliminated size, K kept size, R reduced solve dimension and H is cover embedding dimension (zero for Direct). Existing M6o reports both full buffers.

The needed factor API is a checked solve_in_place_with_scratch plus a required-permutation-scratch query, sharing existing Block::solve_anchored/gather/scatter arithmetic. Today Factor::for_each_block allocates n entries iff its permutation is present. The caller-owned API must validate factor/work/permutation dimensions before mutation, preserve padding and test no-permutation, disconnected/interleaved blocks, ground/cover cases, error/reuse and allocation counts. Old convenience APIs must preserve behavior. Exact retained factor capacities remain a separate required API; scratch removal does not establish setup admission.

The current within buffers already contain sufficient dead storage, so this integration need not enlarge LocalSolver::scratch_size or add a generic extra-scratch trait:

- Direct: R=factor.n(), H=0. After copying rhs[N..N+R] into sol[L..L+R], that RHS region is dead. Back-substitution only reads rhs[..L]. Reuse precisely rhs[N..N+R] for the factor permutation scratch, disjoint from the factor values in sol. Grounding/gauge handling reads only solved sol values afterward. The slice is R long even when auxiliary ground coordinates make R>K.
- Cover: R=K=m and H=inner.n(). The existing live cover values occupy rhs[N+R..N+R+H]. The factor's permutation scratch can use sol[L+R..L+R+H]; this is beyond the kept solution region. Since S=N+R+H=L+2m+H, its remaining sol tail has m+H entries, at least H. Use split_at_mut at L+R to obtain disjoint kept-output and permutation slices. Existing post-solve mean/unfold only reads/writes sol[..N], which ends at L+R; the scratch tail remains dead.

Factor permutation gather initializes its full scratch prefix before block solve; qualify poisoned buffers to prove no stale tail read, rather than assuming zero initialization. Capture old exact outputs before any API change. A successful liveness proof removes a hidden allocation without increasing the already charged outer payload; it does not reduce the two-buffer capacity itself or prove every future factor layout fits. Private signatures may change, but owner wire formats and old public local-solver contract can remain unchanged.

Potential delivery is a separately pinned owner fork of the exact upstream crate revision, with original license/provenance and explicit source registration in within's deny policy, followed by a reviewed within integration and paired MultiwayMG pins. This is a plan only: no approx-chol fork, new remote, vendoring, source copy into MultiwayMG or factor API change has been performed. Full checked construction/fill/fallback overlap and numerical-range eligibility remain later gates.
